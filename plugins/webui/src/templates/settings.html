Professors

Each professor needs a Princeton AI Sandbox API key (from OIT) before they can use this tool. Keys are never shown once saved — only whether one is set.

The netID is the university username this person signs in with — jh43, not Jeff Heller and not an email address. It is how the sandbox knows one person from another: it picks their API key, names their usage file, and is what gets typed to run a command as them. Letters and digits only, and it can't be changed later without removing them and adding them again. The display name is only ever shown to people, so write it however reads best. A backup key, if they have one, is used automatically whenever the primary key stops working.

Shared settings & alternate endpoints

A shared settings file lets a group of installations (e.g. everyone you manage) use the same tuned runtime defaults. Alternate-endpoint credentials are the API keys for any non-default AI endpoints defined in settings.default.toml or preferences.toml.

Point this at a file your group already has. The name is yours to choose — what's stored is the path, not the name.

Looking after the shared file yourself? Download a draft listing every setting this sandbox and its plugins have, all commented out, with each author's explanation. Uncomment what the group should share, rename it if you like, put it somewhere everyone can read, and tell each member to enter that path above. If this installation already points at a shared file, its decisions are carried across and anything new since is marked NEW:.

The first opens a list of every setting, with what each one does, so you can tick what the group should share. The second hands you the same file with everything commented out, to edit in a text editor.

# preferences.toml [endpoints.my_cluster] name = "My HPC Cluster" base_url = "http://my-cluster.internal:8000/v1" openai_compatible = true default_model = "llama-3-70b-instruct"

Endpoint definitions (base URL, timeout, etc.) aren't edited from here — add or change them by hand in settings.default.toml or preferences.toml, following the snippet above, then set the matching credential below. See docs/configuration.md for the full field reference.
