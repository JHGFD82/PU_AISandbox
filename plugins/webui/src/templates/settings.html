Conversation Attachment Storage

Every conversation is stored within the data folder that is installed with this package (typically placed in your user folder unless you specify otherwise). Chat messages and settings are stored in folders for each conversation, and you can include other files based on the choices you select below.

Any changes to these settings will apply to new conversations, but existing conversations will retain their current content.

Shared settings

If you are part of a team with multiple users, you can share settings across all installations.

Set the path above to the location of your shared settings file, if one has been created for your team.

Create a shared settings file for your team

Use the Shared Settings Picker to create a new shared settings file in a new tab, or download the draft to edit it manually in a text editor.

Alternate AI endpoints

An AI service other than the Princeton AI Sandbox — a model on a cluster, or a provider's own API. Calls are counted but carry no cost and are reported separately.

Adding a new API endpoint

# preferences.toml [endpoints.my_cluster] name = "My HPC Cluster" base_url = "http://my-cluster.internal:8000/v1" openai_compatible = true default_model = "llama-3-70b-instruct"

API endpoints are defined in one of two ways:

  1. By adding a new section to the preferences.toml file, following the pattern shown in the snippet above.
  2. By adding a new section to the shared settings file used by your team, following the pattern shown in the snippet above.

If needed, the API key for an endpoint belongs in settings.toml, in the same folder as either of the above-mentioned settings files, using the following pattern:

[endpoints.my_cluster] key = "..."

Keys can be stored within the preferences.toml file or shared settings file, however they are stored as plain text which can pose serious security risks if not handled properly.

Adding a new model

Refer to the Princeton AI Sandbox Service article on Service Now for the list of models available in the AI Sandbox. Model names are constructed with both provider and model name, separated by a slash — for example:

  • openai/gpt-5.2
  • anthropic/claude-opus-4-8
  • google/gemini-3-pro-preview
  • mistral/mistral-7b-instruct-v0.1
  • meta/llama-3-70b-instruct
